# Lista de compliance

Reglas de seguridad del HR Assistant y dónde se cumplen. Las que empiezan con «En producción»
se revisan solas al arrancar con `ENVIRONMENT=production` (`compliance.enforce`, llamada al
inicio de `create_app`): si alguna falla, el proceso no arranca y el error nombra la regla,
nunca un valor (ADR 0012). Las demás se cumplen siempre, en cualquier entorno.

| Regla | Dónde está en el código | Cómo se comprueba |
| --- | --- | --- |
| En producción no se usa el modelo simulado (`MODEL_PROVIDER` distinto de `fake`) | `app/compliance.py`, `violations` (`RULE_REAL_MODEL`) | `tests/test_compliance.py::test_production_reports_every_broken_rule_without_the_keys`; escenario «Production refuses to start with an unsafe configuration» (`uses the fake model`); `verification/contract/test_contract_04.py::test_production_refuses_the_fake_model` |
| En producción `API_KEYS` no está vacía | `app/compliance.py`, `violations` (`RULE_KEYS_PRESENT`) | Escenario «Production refuses to start with an unsafe configuration» (`has no API keys`) |
| En producción cada clave tiene 16 caracteres o más | `app/compliance.py`, `violations` (`MIN_API_KEY_LENGTH`) | Escenario «Production refuses to start with an unsafe configuration» (`has a key of 15 characters`); `tests/test_compliance.py` |
| En producción, con `LANGSMITH_TRACING=true`, `HIDE_INPUTS` y `HIDE_OUTPUTS` valen `true` | `app/compliance.py`, `violations` (`RULE_TRACES_HIDDEN`) | Escenario «Production refuses to start with an unsafe configuration» (`sends traces without hiding the texts`); `tests/test_compliance.py` |
| Una configuración de producción segura arranca | `app/main.py`, `create_app` (llama a `enforce`) | Escenario «Production starts with a safe configuration» |
| Fuera de producción no se exige nada; `ENVIRONMENT` solo acepta `development` o `production` | `app/compliance.py`, `violations`; `app/config.py`, `Settings._validate_access` | `tests/test_compliance.py::test_development_requires_nothing`; `tests/test_config_production.py::test_misspelled_environment_is_rejected` |
| `POST /ask` y `GET /metrics` exigen `X-API-Key`; sin clave o con una inválida, `401 {"detail": "invalid or missing API key"}` | `app/security.py`, `build_require_client`; `app/main.py`, `_register_routes` | Escenario «A request without a valid key is rejected»; `verification/contract/test_contract_04.py` |
| `/`, `/health` y `/docs` no piden clave | `app/main.py`, `_register_routes` | Escenario «The page, the health check and the docs need no key» |
| Las claves se comparan con `hmac.compare_digest` contra todas, sin cortar al encontrar una | `app/security.py`, `ApiKeyAuth.identify` | `tests/test_security.py::test_wrong_empty_or_missing_key_identifies_nobody` y revisión de código |
| La clave nunca se escribe en el log, la traza ni un error; solo el nombre del cliente | `app/security.py` (`ApiKey.key` con `repr=False`); `app/middleware.py`, `_record` (no registra encabezados); `app/main.py`, `AskService.answer` | Escenarios «A request without a valid key is rejected» y «A client with a valid key is answered and named in the log» (`the log does not contain the key that was sent`); `tests/test_config_production.py::test_api_keys_are_read_but_never_shown_in_repr` |
| El nombre del cliente va en `request`, `agent_run`, `audit` y en los metadatos de la traza | `app/middleware.py`, `_record`; `app/main.py`, `AskService.answer`; `app/tracing.py`, `LangSmithTracer.wrap` | Escenario «A client with a valid key is answered and named in the log»; `tests/test_api.py::test_rejected_request_logs_a_null_client` |
| `API_KEYS` mal formada impide arrancar; el error dice el número de la entrada y su largo, nunca su valor | `app/security.py`, `parse_api_keys` y `_entry_error` | `tests/test_security.py`; `verification/contract/test_contract_04.py::test_a_broken_api_keys_never_leaks_the_key` |
| El nombre del cliente solo usa `[A-Za-z0-9._-]`, para que no inyecte texto en el log | `app/security.py`, `CLIENT_NAME_PATTERN` | `tests/test_security.py::test_malformed_api_keys_are_rejected` |
| Más de `RATE_LIMIT_PER_MINUTE` peticiones por cliente en 60 s dan `429 {"detail": "rate limit exceeded"}` con `Retry-After` | `app/ratelimit.py`, `RateLimiter.check` (reloj inyectado); `app/security.py`, `build_require_client` | Escenarios «A client that asks too often is told when to retry», «The limit frees up once the minute has passed» y «A client at its limit does not block another client»; `tests/test_ratelimit.py`; `verification/contract/test_contract_04.py::test_too_many_requests_returns_429_with_retry_after` |
| La página guarda la clave en `sessionStorage` (nunca en `localStorage` ni en su código), en un campo de tipo contraseña, y la manda en `X-API-Key` | `app/static/index.html` | `tests/test_api.py::test_page_keeps_the_key_in_a_password_field_and_session_storage`; pruebas de punta a punta de `e2e/` |

## Datos personales (PII)

| Regla | Dónde está en el código | Cómo se comprueba |
| --- | --- | --- |
| En producción `PII_DETECTION` vale `true` | `app/compliance.py`, `violations` (`RULE_PII_ON`) | `tests/test_pii_wiring.py::test_production_requires_pii_detection_but_development_does_not`; escenario «Production refuses to start without PII detection»; `verification/contract/test_contract_05.py::test_production_refuses_to_start_without_pii_detection` |
| `PII_DETECTION` solo acepta `true` o `false`; `OUTPUT_MAX_CHARS` es un entero de 1 o más | `app/config.py`, `_pii_values` y `Settings._validate_access` | `tests/test_config_pii.py` |
| La PII se detecta en local, con expresiones regulares y sin servicios externos: `email`, `phone`, `curp`, `rfc`, `card` (con Luhn) y `clabe`; un número de empleado no es PII | `app/pii.py`, `detect`, `mask` y `luhn_ok` | `tests/test_pii.py` |
| El detector devuelve solo los tipos, nunca los valores | `app/pii.py`, `detect`, `detect_all` y `MaskResult` | `tests/test_pii.py::test_several_types_come_in_a_fixed_order_and_without_values` |
| Una pregunta o un mensaje del historial (aunque quede fuera de la ventana) con PII da `422 {"detail": "sensitive data detected: <tipos>", "request_id"}` sin llamar al modelo y sin repetir el dato | `app/main.py`, `AskService._block_sensitive_input` y `_register_sensitive_data`; `app/guardrails.py`, `SensitiveDataError` | Escenarios «A question with personal data is rejected without calling the model» y «Personal data in an old history message is rejected even outside the window»; `verification/contract/test_contract_05.py` |
| La PII de la respuesta del modelo se reemplaza por `[EMAIL]`, `[PHONE]`, `[CURP]`, `[RFC]`, `[CARD]` o `[CLABE]` y `pii_masked` lista los tipos | `app/guardrails.py`, `validate_output`; `app/main.py`, `AskService.answer` | Escenario «Personal data in the model answer is masked and audited»; `tests/test_guardrails.py` |
| Una respuesta vacía se cambia por el mensaje de tope de pasos; la PII se enmascara antes de recortar a `OUTPUT_MAX_CHARS` | `app/guardrails.py`, `validate_output` | Escenario «An empty model answer becomes the step limit message»; `tests/test_guardrails.py` |
| Cada detección escribe `pii_detected` con `request_id`, `client`, `where` y `types`, nunca el valor | `app/main.py`, `AskService._record_pii` | Escenarios «Personal data in the model answer is masked and audited» y «A blocked question is audited and counted without its value» (`the log does not contain`) |
| `/metrics` cuenta `pii_blocked` y `pii_masked` | `app/metrics.py`, `add_pii_blocked`, `add_pii_masked` y `pii_counts`; `app/main.py`, `read_metrics` | Escenarios del punto anterior (`the metrics show`); `verification/contract/test_contract_05.py::test_metrics_count_blocked_questions` |
| La traza lleva los tipos en `pii_types` (tramos `pii_input` y `pii_output`, cuya única entrada son los tipos) | `app/tracing.py`, `LangSmithTracer.wrap`; `app/main.py`, `report_pii_types` | `tests/test_pii_wiring.py::test_trace_metadata_carries_the_pii_types_only` |
| La página muestra «Tu pregunta contiene datos sensibles; elimínalos y vuelve a intentar» con un `422` por datos sensibles | `app/static/index.html`, `isSensitiveData` y `errorMessage` | `tests/test_pii_wiring.py::test_page_shows_the_sensitive_data_message`; `e2e/test_chat_page.py` |
